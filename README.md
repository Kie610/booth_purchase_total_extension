# booth_purchase_total_extension

BOOTH ([accounts.booth.pm/orders](https://accounts.booth.pm/orders)) の購入履歴から、
実際に支払った合計金額を **注文単位** で正確に集計するブラウザ拡張機能です。

## 直した不具合

既存の公開拡張では、1つの注文で同じショップの商品を複数購入した場合、
購入履歴一覧ページ上でその注文が商品数だけ行として重複表示されることが原因で、
注文の支払金額が複数回加算されてしまう問題がありました。

この拡張では、一覧ページの全ページを巡回したあと **注文IDで重複除去** してから、
注文詳細ページの「お支払金額」(商品代・送料など込みの実際の支払総額)を
1注文につき1回だけ取得して合計するため、重複カウントが発生しません。

## リポジトリ構成

```
extension/          読み込み対象の拡張機能本体
  manifest.json     Manifest V3 定義
  common.js         定数・日付解析・月別集計・期間集計・ストレージ操作の共通処理
  popup.html/css/js ポップアップ(収集済み合計の概要表示と集計ページへの導線)
  dashboard.html/css/js
                    集計ページ(注文履歴の取得・範囲を指定した金額収集・一括集計・
                    中断・進捗表示・年別月別集計・注文内訳)
test/               ブラウザ上で動く簡易テスト(test/README.md 参照)
LICENSE             MIT License
```

ビルド手順はありません。`extension/` をそのままブラウザに読み込みます。

## インストール方法

### Chrome (Chromium系ブラウザ共通)

1. `chrome://extensions` を開く
2. 右上の「デベロッパーモード」をONにする
3. 「パッケージ化されていない拡張機能を読み込む」から `extension` フォルダを選択

### Firefox

1. `about:debugging#/runtime/this-firefox` を開く
2. 「一時的なアドオンを読み込む」から `extension/manifest.json` を選択

※ Firefoxの「一時的なアドオン」はブラウザ再起動で消えるため、恒久的に使いたい場合は
`about:config` で `xpinstall.signatures.required` を無効化するか、
Firefox向けにMozillaの署名を通す必要があります。

## 使い方

1. `accounts.booth.pm` に事前にログインしておく
2. 拡張機能のアイコンをクリックし、ポップアップの「集計ページを開く」を押す

集計は**専用ページ(タブ)上で実行される**ため、取得中も他のタブやウィンドウを
自由に操作できます。ポップアップを閉じても処理は止まりません。
ポップアップからは進捗と収集済みの合計が確認でき、実行中は
「集計ページを表示」でいつでもページに戻れます。

注文数が多いと一度に全件取得するのは時間がかかるため、処理を2段階に分けて
少しずつ進められるようになっています。

### ① 注文履歴の取得

購入履歴の一覧ページを巡回し、注文番号・注文日時・ステータスを取得します。
金額はここでは取りに行かないため、比較的短時間で終わります。
新しい注文が増えたときは、これを再実行すると一覧が最新になります。

### ② 金額の収集

注文詳細ページから「お支払金額」を取得します。月ごとに
**注文数 / 収集済み / 未収集** の件数が表示されるので、未収集が残っている月を
見ながら範囲を指定して収集できます。

- 月の行をクリックすると、その月が範囲に設定されます
- 「未収集のある範囲を選択」で、未収集が残る最古〜最新の月をまとめて選択できます
- 収集ボタンの横に、その範囲で実際に取得しにいく件数が表示されます
- 「キャッシュを無視して指定範囲を再取得」にチェックを入れると、
  収集済みの注文も指定範囲だけ取り直します(範囲外のキャッシュは保持されます)
- 注文日時が読み取れなかった注文は月の範囲で指定できないため、
  「まとめて一括集計」で収集します(通常は発生しません)

### まとめて一括集計

①と②をまとめて実行します。従来通りの動作で、「キャッシュを無視して全件再取得」に
チェックを入れるとすべての注文を取り直します。

### 共通

サーバー負荷軽減のため、各リクエストの間に約0.25秒の間隔を空けています。
時間がかかりすぎる場合は「中断」でいつでも止められます。
取得した金額はブラウザのローカルストレージに逐次保存されるため、
中断やタブを閉じた後に再実行すると、未収集の注文だけを取得して続きから進みます。

画面上部にはタイトルが固定表示されます。画面下部には**合計支払額と今年の合計**
(それぞれ収集済みの件数付き)が固定表示され、実行中はその上に進捗バーと
「中断」ボタンが出るため、どこまでスクロールしていても状況が分かります。

集計結果は収集済みの合計金額に加えて、**年別・月別の内訳**
(年の行をクリックで月別を展開)と注文ごとの一覧を表示します。
注文ごとの一覧は件数が多くなるため、折りたたんだ状態で表示されます。
一覧では「未収集」(まだ取得していない)と「取得失敗」(取得したが金額を読めなかった)
を区別して表示します。

## 集計対象について

- デフォルトで **キャンセルされた注文のみ除外** し、それ以外(発送完了・支払済み・未払いなど)は
  すべて合計に含めます。
- 集計は注文詳細ページの「お支払金額」を用いるため、送料やBOOST(投げ銭)分も
  含めた実際の支払総額になります。

## 既知の制限

- 集計ページのタブを閉じると処理は中断されます(Service Workerでの完全なバックグラウンド
  実行には未対応)。ただし取得済みの金額は保存されているため、再実行すれば続きから取得します。
- BOOTHのページ構造(HTML)が変更された場合、セレクタの調整が必要になる可能性があります。
- 集計中、取得1件につき以下のCSP違反がブラウザのコンソールに記録されます。

  ```
  Loading the script 'https://www.google.com/recaptcha/enterprise.js?...'
  violates the following Content Security Policy directive: "script-src 'self'"
  ```

  BOOTHのレスポンスに `Link: <...enterprise.js>; rel=preload; as=script` ヘッダが
  含まれており、ブラウザがヘッダの時点で先読みを試みるためです。拡張機能ページの
  CSPが要求の発行前にブロックしているため**通信は発生せず、集計結果にも影響しません**。
  fetch側から先読みを抑止する手段は無く、CSPに `google.com` を追加すれば消せますが、
  それは読み込みを許可する意味になりMV3のリモートコード禁止に抵触するため行いません。

## プライバシー

購入履歴・金額はすべて閲覧中のブラウザ内(`storage.local`)にのみ保存され、
外部へ送信することはありません。取得した購入データはこのリポジトリには含めません。
