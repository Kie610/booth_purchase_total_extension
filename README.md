# BOOTHお買いものレポート

BOOTH ([accounts.booth.pm/orders](https://accounts.booth.pm/orders)) の購入履歴から、
実際に支払った合計金額を **注文単位** で正確に集計するブラウザ拡張機能です。

## 直した不具合

既存の公開拡張では、1つの注文で同じショップの商品を複数購入した場合、
購入履歴一覧ページ上でその注文が商品数だけ行として重複表示されることが原因で、
注文の支払金額が複数回加算されてしまう問題がありました。

この拡張では、一覧ページの全ページを巡回したあと **注文IDで重複除去** してから、
注文詳細ページの「お支払金額」(商品代・送料など込みの実際の支払総額)を
1注文につき1回だけ取得して合計するため、重複カウントが発生しません。

  purchase-examples.js

ビルド手順はありません。`extension/` をそのままブラウザに読み込みます。
アイコンは生成済みのPNGをコミットしてあるため、変更しない限り再生成は不要です。

## インストール方法

### Chrome (Chromium系ブラウザ共通)

1. `chrome://extensions` を開く
2. 右上の「デベロッパーモード」をONにする
3. 「パッケージ化されていない拡張機能を読み込む」から `extension` フォルダを選択

### Firefox

1. `about:debugging#/runtime/this-firefox` を開く
2. 「一時的なアドオンを読み込む」から `extension/manifest.json` を選択

※ Firefoxの「一時的なアドオン」はブラウザ再起動で消えるため、恒久的に使いたい場合は
`about:config` で `xpinstall.signatures.required` を無効化するか、
Firefox向けにMozillaの署名を通す必要があります。

## 使い方

1. `accounts.booth.pm` に事前にログインしておく
2. 拡張機能のアイコンをクリックし、ポップアップの「集計ページを開く」を押す

集計は**専用ページ(タブ)上で実行される**ため、取得中も他のタブやウィンドウを
自由に操作できます。ポップアップを閉じても処理は止まりません。
ポップアップからは進捗と収集済みの合計が確認でき、実行中は
「集計ページを表示」でいつでもページに戻れます。

注文数が多いと一度に全件取得するのは時間がかかるため、処理を2段階に分けて
少しずつ進められるようになっています。

### ① 注文履歴の取得

購入履歴の一覧ページを**新しい順に**巡回し、注文番号・注文日時・ステータスを取得します。
金額はここでは取りに行かないため、比較的短時間で終わります。

**すでに最古まで取得できている場合は、取得済みの注文に到達した時点で停止します。**
2回目以降は増えた分だけを取得するためすぐに終わり、「以降は読み込み済み」と表示されます。

一覧は新しい順に辿るため、途中で失敗すると**新しい方だけが取得され、それより古い注文が
丸ごと欠けた状態**になります。これに気づけるよう、確実に取得できた範囲を内部に記録し、
UIに表示します。

- `取得済みの範囲: 全期間 (最古の注文 2024年2月1日 12:34)` — 最古まで到達済み
- `取得済みの範囲: 最新 〜 2025年8月10日 ...` — 途中で終了。これより古い注文は未取得

**途中で終わっている場合は、既知の注文に当たっても停止せず、最後のページまで辿って
抜けている範囲を取得します。** 中断のあとにもう一度「注文履歴を取得」を押すだけで
穴が埋まるため、全件再取得は不要です(既知の注文はページを読むだけで、取得済みの
金額は取り直しません)。

中断や通信失敗があっても、そこまでに取得できた分は保存した上で「未完了」として記録するので、
範囲の表示が実態と食い違うことはありません。キャッシュが壊れている場合など、
記録そのものを信用できないときは「キャッシュを無視して全件再取得」で最古まで取り直せます。

### ② 金額の収集

注文詳細ページから「お支払金額」を取得します。**年ごとにまとまった表**で
**注文数 / 収集済み / 未収集** の件数が表示されるので、未収集が残っている期間を
見ながら範囲を指定して収集できます。

- 年の行の ▸ をクリックすると、その年の月別を開閉できます(初期状態は閉じています)
- 年の行をクリックすると、その年全体が範囲に設定されます
- 月の行をクリックすると、その月が範囲に設定されます
- 「未収集のある範囲を選択」で、未収集が残る最古〜最新の月をまとめて選択できます
- 収集ボタンの横に、その範囲で実際に取得しにいく件数が表示されます
- 「キャッシュを無視して指定範囲を再取得」にチェックを入れると、
  収集済みの注文も指定範囲だけ取り直します(範囲外のキャッシュは保持されます)
- 注文日時が読み取れなかった注文は月の範囲で指定できないため、
  「まとめて一括集計」で収集します(通常は発生しません)

### まとめて一括集計

①と②をまとめて実行します。従来通りの動作で、「キャッシュを無視して全件再取得」に
チェックを入れるとすべての注文を取り直します。

### 共通

サーバー負荷軽減のため、各リクエストの間に約0.25秒の間隔を空けています。
時間がかかりすぎる場合は「中断」でいつでも止められます。
取得した金額はブラウザのローカルストレージに逐次保存されるため、
中断やタブを閉じた後に再実行すると、未収集の注文だけを取得して続きから進みます。

画面上部にはタイトルが固定表示されます。画面下部には**合計支払額と今年の合計**
(それぞれ収集済みの件数付き、ギフト分は金額の下)が固定表示され、実行中は
その上に進捗バーと「中断」ボタンが出るため、どこまでスクロールしていても
状況が分かります。

画面下部の右端には「Xで共有」ボタンがあります。押すとXの投稿画面が新しいタブで
開き、次の文面が入力された状態になります。**投稿は行われません**(Xの画面で
自分で確定します)。金額を公開したくない場合は、投稿前に編集するか閉じてください。

```
BOOTHお買いもの振り返り🛍️

合計：¥196,400（128件）
今年：¥40,130（12件）

積み重ねてみると、Apple iPhone 17 Proが買えるくらいの金額になりました。

#BOOTHお買いものレポート
```

未収集の注文が残っている場合、この「合計」は実際より少ない額になります。
そのため、未収集があるとき(または注文履歴を最古まで取得できていないとき)は
確認を挟み、**今年分の未収集だけをその場で収集してから、今年の金額だけを共有**します。
合計の行は出しません。買えるものの比較も、文面に出した今年の金額を基準に選びます。

```
BOOTHお買いもの振り返り🛍️

今年：¥40,130（12件）

積み重ねてみると、ReFa BEAUTECH DRYER SMART Wが買えるくらいの金額になりました。

#BOOTHお買いものレポート
```

集計結果は収集済みの合計金額に加えて、**年別・月別の内訳**
(年の行をクリックで月別を展開)と注文ごとの一覧を表示します。
注文ごとの一覧は件数が多くなるため、折りたたんだ状態で表示され、
展開しても見出し行を固定したスクロール領域に収まります。
一覧では「未収集」(まだ取得していない)と「取得失敗」(取得したが金額を読めなかった)
を区別して表示します。取得失敗の注文は次に集計を実行したときに自動で取り直すので、
全件再取得をしなくても直ります。

### キャッシュ削除

ページ最下部の「キャッシュ削除」を開くと、**注文履歴**と**収集した金額**を
それぞれ個別に削除できます。現在の保存件数が表示され、削除前に確認を求めます。
消したデータはBOOTHから取り直すことになるため、再取得には時間がかかります。

## 集計対象について

- デフォルトで **キャンセルされた注文のみ除外** し、それ以外(発送完了・支払済み・未払いなど)は
  すべて合計に含めます。
- 集計は注文詳細ページの「お支払金額」を用いるため、送料やBOOST(投げ銭)分も
  含めた実際の支払総額になります。
- 支払額に**ギフト分が含まれる場合は、その金額を支払額の左に小さく併記**します
  (合計・年別・月別・注文ごとの内訳・画面下部の固定表示のすべて)。ギフト分は
  支払額に含まれた内訳なので、合計から差し引く扱いにはしていません。
  ギフトが無い注文では何も表示しません。
- ギフト分は、注文詳細ページで「ギフト」の見出しが付いた商品グループに並ぶ
  商品価格(BOOST含む)の合計です。ページ構造が変わって商品を判別できない
  場合は、0円と断定せず「不明」として扱い、何も表示しません。

## 画面の切り替え

ヘッダー左の「☰」から画面を切り替えられます。**収集の実行中でも切り替えられ、
処理は止まりません**(同じページの中で表示を出し分けているため)。

- **お買いものレポート** — 収集と集計を行う既定の画面
- **データ出力** — 収集したデータをCSVで保存する画面
- **データの引っ越し** — バックアップの保存と復元を行う画面

レポート以外の画面では、未収集の注文が残っている場合や注文履歴の取得が途中で
終わっている場合に、**その画面の数字が実際より少なくなることを表示**し、
収集できる画面へ戻るリンクを添えます。

## データ出力(CSV)

「データ出力」の画面から2種類のCSVを保存できます。Excelでそのまま開けるよう
UTF-8のBOM付きで書き出し、金額の列には桁区切りを付けません。

| 種類 | 1行の単位 | 列 |
| --- | --- | --- |
| 注文単位 | 1注文 | 注文番号 / 注文日時 / ステータス / お支払金額 / ギフト額 / 商品合計 / 送料 / 差額 / 商品点数 |
| 商品単位 | 1商品 | 注文番号 / 注文日時 / ステータス / ショップ名 / ショップURL / 商品名 / 単価 / 数量 / BOOST / ギフト |

- 未収集や取得失敗の注文は、0円と区別が付かなくなるため**空欄**にします。
  商品単位のCSVでも、その注文を買っていないように見えないよう行自体は残します。
- 合計は**注文詳細ページの「お支払金額」**から計算しており、商品単価の合計では
  代用していません。配送のある注文には送料が乗るため一致しないからです
  (実例: お支払金額¥4,060 = 商品¥890×4個 + 送料¥500)。
  お支払金額を商品合計と送料で説明しきれない分は「差額」列に出て、画面にも
  件数を表示します(クーポンやポイントなどが考えられます)。

## データの引っ越し(バックアップ／復元)

注文が多いとBOOTHからの再取得に数分かかります（注文1000件で4分以上）。
ブラウザやプロファイルを移すときは「データの引っ越し」の画面から、収集済みの
データをJSONファイルに保存し、移行先で読み込み直してください。
保存されるのは注文履歴と収集した金額だけで、**BOOTHのログイン情報は含まれません**。

復元は入れ替えではなく**併合**です。今あるデータは消えず、同じ注文があれば
収集済みの方を残します。注文履歴の「取得済みの範囲」は、**両方が全期間のときだけ**
全期間のままにします（片方でも途中までだと、つないだ結果に抜けが無いとは
言い切れないため）。読み込んだファイルは形を確かめてから使い、バックアップ以外の
ファイルや壊れたファイルでは何も書き換えません。

## 集計対象について(補足)

- 商品明細(ショップ名・商品名・単価・数量・BOOST・ギフトかどうか)と送料は、
  金額の収集と同時に注文詳細ページから取得します。
- ダウンロード商品と配送商品では注文詳細ページの構造が異なりますが、どちらにも
  対応しています。

## 既知の制限

- 商品明細より前に収集した注文にはショップ名や商品名がありません。該当する注文は
  「未収集」として扱われるため、**再実行すれば自動的に取り直します**
  (「キャッシュを無視して」の指定は不要です)。
- 集計ページのタブを閉じると処理は中断されます(Service Workerでの完全なバックグラウンド
  実行には未対応)。ただし取得済みの金額は保存されているため、再実行すれば続きから取得します。
- 一時的な通信エラーは数回試し直します。それでも取得できなかった注文は**飛ばして
  先へ進み**、件数をまとめて知らせます。飛ばした注文は「未収集」のまま残るので、
  再実行すれば自動で拾い直します(数百件の収集が1件の失敗で止まらないようにするため)。
  ログイン切れの場合だけは、続けても全部失敗するのでその場で止めます。
- BOOTHのページ構造(HTML)が変更された場合、セレクタの調整が必要になる可能性があります。
  一覧をうまく読み取れなかった場合(1件も取れない、ページ送りを追えない)は、
  「全期間を取得済み」とは表示せず警告を出します。合計が実際より少なくなっている
  可能性があるためです。
- 集計中、取得1件につき以下のCSP違反がブラウザのコンソールに記録されます。

  ```
  Loading the script 'https://www.google.com/recaptcha/enterprise.js?...'
  violates the following Content Security Policy directive: "script-src 'self'"
  ```

  BOOTHのレスポンスに `Link: <...enterprise.js>; rel=preload; as=script` ヘッダが
  含まれており、ブラウザがヘッダの時点で先読みを試みるためです。拡張機能ページの
  CSPが要求の発行前にブロックしているため**通信は発生せず、集計結果にも影響しません**。
  fetch側から先読みを抑止する手段は無く、CSPに `google.com` を追加すれば消せますが、
  それは読み込みを許可する意味になりMV3のリモートコード禁止に抵触するため行いません。

## プライバシー

購入履歴・金額はすべて閲覧中のブラウザ内(`storage.local`)にのみ保存され、
外部へ送信することはありません。取得した購入データはこのリポジトリには含めません。
