[資料一覧へ](README.md)。1280×900のChromeで合成48注文を表示し、8画面を確認しました。ギフト画面は幅620pxでも確認しています。購入履歴は実データではありません。

以下は修正前の記録です。後続の修正状況は[HANDOFF.agent.md](../../../HANDOFF.agent.md)を参照してください。

<a id="ux-01"></a>
## UX-01 / P2 / C：全ギフトの表に「自分用のみ」という見出しが付く

根拠: [extension/dashboard-view.js:270](D:/GitHub_WorkSpace/BrowserExtension/booth_purchase_total_extension/booth_purchase_total_extension/extension/dashboard-view.js:270)。

集計対象を「自分用」にしてギフト・注文へ移ると、見出しは「ギフト・注文 （自分用のみ）」のまま、表には全ギフト16件が並びます。対象バーは非表示で、その画面から条件を確認できません。フッターも自分用64,000円、表は全ギフトという別の対象です。

修正案: ギフト画面の見出しを実際の対象に合わせ、フッターが別の集計範囲ならその範囲を明示する。保存されないフィルターを新たに永続化する必要はありません。

## UX-02 / P2 / C：主要ボタンの文字コントラストが不足する

根拠: [extension/dashboard.css:711](D:/GitHub_WorkSpace/BrowserExtension/booth_purchase_total_extension/booth_purchase_total_extension/extension/dashboard.css:711)、[extension/dashboard.css:20](D:/GitHub_WorkSpace/BrowserExtension/booth_purchase_total_extension/booth_purchase_total_extension/extension/dashboard.css:20)、[extension/dashboard.css:2197](D:/GitHub_WorkSpace/BrowserExtension/booth_purchase_total_extension/booth_purchase_total_extension/extension/dashboard.css:2197)。

有効な「一括で集計を実行」ボタンは、14px・通常ウェイトの白文字と背景#fc4d50で、計算したコントラスト比は**3.3246:1**です。通常サイズ文字の基準4.5:1に届きません。無効ボタンやロゴの免除は、この操作ボタンには当たりません。[W3Cの基準](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

修正案: 操作ボタンの文字と背景の組み合わせを調整し、主要操作・選択状態・hoverをライト／ダーク両テーマで確認する。ブランドロゴの色まで変更する必要はありません。今回の動的測定はライトテーマの有効ボタンです。

## UX-03 / P3 / C：バックアップへ含む情報と除外する情報を画面で説明しない

根拠: [extension/dashboard.html:673](D:/GitHub_WorkSpace/BrowserExtension/booth_purchase_total_extension/booth_purchase_total_extension/extension/dashboard.html:673)、[extension/backup.js:16](D:/GitHub_WorkSpace/BrowserExtension/booth_purchase_total_extension/booth_purchase_total_extension/extension/backup.js:16)、[README.md:561](D:/GitHub_WorkSpace/BrowserExtension/booth_purchase_total_extension/booth_purchase_total_extension/README.md:561)。

画面は「保存されるのは注文履歴と収集した金額だけ」と案内しますが、商品情報・手動割当・商品に保持するgiftIdも入ります。一方、ギフト受取状況とメモは入りません。READMEには後者の仕様がありますが、引っ越し操作の画面にはありません。

修正案: 保存される主要データを示し、「受取状況・メモは再取得が必要」と明記する。バックアップに含めない現仕様自体を不具合には数えていません。第三者へ共有しない注意書きは既にあります。

## UX-04 / P3 / C：消去方法の案内と残る情報が分かりにくい

根拠: [extension/dashboard.js:950](D:/GitHub_WorkSpace/BrowserExtension/booth_purchase_total_extension/booth_purchase_total_extension/extension/dashboard.js:950)、[extension/dashboard.html:280](D:/GitHub_WorkSpace/BrowserExtension/booth_purchase_total_extension/booth_purchase_total_extension/extension/dashboard.html:280)、[PRIVACY.md:40](D:/GitHub_WorkSpace/BrowserExtension/booth_purchase_total_extension/booth_purchase_total_extension/PRIVACY.md:40)。

注文履歴と金額を両方削除しても、ギフトUUID・私的メモ・手動割当は残ります。READMEにある既定仕様ですが、削除操作には残る情報の一覧や、それらをまとめて消す導線がありません。PRIVACYの削除場所は「データの引っ越し」と書かれていますが、実際のキャッシュ削除は「お買いものレポート」にあります。

修正案: 既存の2ボタンを勝手に全削除へ変えず、残る項目と正しい操作場所を説明する。購入関連情報全体を消す必要に応じて、対象一覧を確認できる消去操作を用意する。外部から読める脆弱性という判定ではありません。

## UX-05 / P3 / C：1年分だけのデータで比較年の選択欄が空になる

根拠: [extension/dashboard-insights-view.js:742](D:/GitHub_WorkSpace/BrowserExtension/booth_purchase_total_extension/booth_purchase_total_extension/extension/dashboard-insights-view.js:742)、[extension/dashboard-insights-view.js:769](D:/GitHub_WorkSpace/BrowserExtension/booth_purchase_total_extension/booth_purchase_total_extension/extension/dashboard-insights-view.js:769)。

2026年分しかない合成データで、比較年のselectには選択肢が無いのに、カードとグラフは2025年を表示します。計算は前年を0として扱う一方、選択肢は注文のある年だけから作るためです。

修正案: 「前年（購入記録なし）」を選択表示するか、比較対象なしを説明してselectを無効にする。不完全な取得範囲のときに、単に記録が無いことを0円確定と誤認させないことも確認します。
